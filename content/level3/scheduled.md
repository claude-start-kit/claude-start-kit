# 예약 작업

> 정해진 시각이나 간격으로 **Claude가 같은 일을 반복**하게 합니다. "5분마다 배포가 끝났는지 확인", "매일 아침 9시에 변경 사항 요약"처럼 쓰입니다.

## 먼저 고르기: 세 가지 방법
Claude Code에는 예약 방법이 세 가지 있습니다. **내 컴퓨터가 꺼져도 되는지**가 가장 큰 차이입니다.

| | 클라우드 (루틴) | 데스크톱 | `/loop` |
|---|---|---|---|
| 실행 위치 | 클라우드 (Anthropic 관리) | 내 컴퓨터 | 내 컴퓨터 |
| 컴퓨터가 켜져 있어야 | 아니오 | **예** | **예** |
| 세션이 열려 있어야 | 아니오 | 아니오 | **예** |
| 재시작 후에도 유지 | 예 | 예 | `--resume`으로 일부 복원 |
| 내 PC 파일 접근 | 아니오 (새로 복제한 저장소) | 예 | 예 |
| 최소 간격 | 1시간 | 1분 (입력 양식에서는 1시간) | 1분 |

> **고르는 기준**
> - 내 컴퓨터가 꺼져도 **안정적으로** 돌아야 한다 → **클라우드**
> - **내 PC의 파일·도구**가 필요하다 → **데스크톱**
> - 지금 작업하면서 **잠깐 확인**하고 싶다 → **`/loop`**

이 레슨은 가장 쉽게 시작할 수 있는 **`/loop`** 를 중심으로 설명합니다. 클라우드와 데스크톱 예약은 [루틴 문서](https://code.claude.com/docs/ko/routines)와 [데스크톱 예약 작업 문서](https://code.claude.com/docs/ko/desktop-scheduled-tasks)를 참고하세요.

## /loop로 반복 실행하기
`/loop`는 **세션을 열어 둔 동안** 프롬프트를 반복 실행하는 기본 제공 스킬입니다. 간격과 프롬프트는 각각 생략할 수 있고, 무엇을 주느냐에 따라 동작이 달라집니다.

| 입력 | 예 | 동작 |
|---|---|---|
| 간격 + 프롬프트 | `/loop 5m 배포가 끝났는지 확인해 줘` | **고정 간격**으로 실행 |
| 프롬프트만 | `/loop CI가 통과했는지 확인해 줘` | **Claude가 간격을 정함** |
| 간격만, 또는 아무것도 | `/loop` | **기본 점검 프롬프트**(또는 `loop.md`) 실행 |

### 고정 간격
```text
/loop 5m 배포가 끝났는지 확인하고 어떻게 됐는지 알려 줘
```
- 단위: `s`(초) · `m`(분) · `h`(시간) · `d`(일). `30m`처럼 앞에 쓰거나 "2시간마다"처럼 뒤에 써도 됩니다
- 초 단위는 **분 단위로 올림**됩니다 (cron이 1분 단위라서)
- `7m`, `90m`처럼 깔끔하지 않은 간격은 가까운 값으로 바뀌고 Claude가 알려 줍니다

### Claude가 간격을 정하게 하기
간격을 빼면 Claude가 **매번 1분~1시간 사이**에서 알맞은 간격을 고릅니다. 빌드가 끝나가거나 PR이 활발하면 짧게, 할 일이 없으면 길게 잡습니다. 고른 간격과 이유는 매 반복 끝에 표시됩니다.
```text
/loop CI가 통과했는지 확인하고 리뷰 댓글에 대응해 줘
```

### 프롬프트 없이 `/loop`
프롬프트를 생략하면 기본 점검 프롬프트가 아래 순서로 일합니다.
1. 대화에서 **끝내지 못한 일** 이어서 하기
2. 현재 브랜치의 **PR 돌보기** (리뷰 댓글, 실패한 CI, 병합 충돌)
3. 할 일이 없으면 **정리 작업** (버그 탐색, 단순화)

푸시나 삭제 같은 일은 세션의 **권한 확인**을 그대로 거칩니다.

### 나만의 기본 프롬프트: `loop.md`
기본 점검 프롬프트 대신 **내 지침**을 쓰려면 `loop.md` 파일을 만듭니다.

| 경로 | 범위 |
|---|---|
| `.claude\loop.md` | 이 프로젝트 (둘 다 있으면 이쪽이 우선) |
| `%USERPROFILE%\.claude\loop.md` | 내 모든 프로젝트 |

형식은 자유로운 마크다운이며, `/loop`에 직접 입력할 프롬프트처럼 쓰면 됩니다.
```markdown
`release/next` PR을 확인해 줘. CI가 실패했으면 실패한 작업의 로그를 가져와
원인을 진단하고 최소한의 수정을 푸시해. 새 리뷰 댓글이 있으면 하나씩 대응하고
스레드를 해결 처리해. 모두 통과했고 조용하면 한 줄로만 알려 줘.
```
- 명령줄에 프롬프트를 직접 주면 `loop.md`는 **무시**됩니다
- 파일을 고치면 **다음 반복부터** 바로 적용됩니다
- 25,000바이트를 넘는 부분은 잘립니다

### 스킬을 반복 실행하기
```text
/loop 20m /review-pr 1234
```
단, 예약 실행은 **Claude가 스스로 호출할 수 있는 스킬**만 실행합니다. `/permissions`, `/model`, `/clear` 같은 기본 제공 명령이나 `disable-model-invocation: true`인 스킬은 실행되지 않고 **그냥 글자로** 전달됩니다.

### 멈추기
| 종류 | 멈추는 법 |
|---|---|
| Claude가 간격을 정하는 루프 | 다음 반복을 기다리는 중에 빈 입력창에서 `Esc` (또는 Claude가 쉬는 중 `Ctrl+C`) |
| 고정 간격 루프 | Claude에게 **"배포 확인 루프를 취소해 줘"** 라고 요청. `Esc`·`Ctrl+C`로는 멈추지 않습니다 |

## 한 번만 알려 달라고 하기
일회성 알림은 `/loop` 없이 **말로** 요청합니다. 한 번 실행하고 스스로 삭제됩니다.
```text
오후 3시에 릴리스 브랜치 푸시하라고 알려 줘
```
```text
45분 뒤에 통합 테스트가 통과했는지 확인해 줘
```

## 예약 작업 관리하기
말로 요청하면 됩니다.
```text
지금 예약된 작업이 뭐가 있어?
```
```text
배포 확인 작업을 취소해 줘
```
내부적으로는 도구 세 개를 씁니다.

| 도구 | 역할 |
|---|---|
| `CronCreate` | 새 작업 예약 (cron 식, 프롬프트, 반복 여부) |
| `CronList` | 작업 목록 (ID, 일정, 다음 실행 시각, 프롬프트) |
| `CronDelete` | ID로 작업 취소 |

작업마다 8자리 ID가 있고, 한 세션에 **최대 50개**까지 예약할 수 있습니다.

## 어떻게 실행되나
- 1초마다 실행할 때가 됐는지 확인하고, 해당 프롬프트는 **내 턴 사이에** 실행됩니다. Claude가 답하는 중이면 그 턴이 끝날 때까지 기다립니다
- 시간은 **내 컴퓨터의 시간대** 기준입니다. `0 9 * * *`는 UTC가 아니라 내가 있는 곳의 오전 9시입니다

### 실행 시각이 조금 어긋나는 이유 (지터)
모든 사용자의 작업이 정각에 몰리지 않도록 Claude Code가 실행 시각을 **살짝 흩뜨립니다.**

| 일정 | 실제 시작 |
|---|---|
| 5분마다 (`*/5 * * * *`) | 이전 실행 **4분 45초 뒤** |
| 10분마다 | 0~5분 늦음 |
| 30분마다 | 0~15분 늦음 |
| 1시간마다, 매일 | 0~30분 늦음 |

- 한 번만 실행하는 작업이 **정각·30분**이면 최대 90초 **일찍** 실행될 수 있습니다. 시각이 중요하면 `0 9 * * *` 대신 `3 9 * * *`처럼 **정각을 피하세요**

### 7일이 지나면 사라집니다
반복 작업은 만든 지 **7일 뒤 마지막으로 한 번 실행되고 자동 삭제**됩니다. 잊힌 루프가 계속 도는 것을 막기 위해서입니다. 더 오래 돌려야 하면 취소 후 다시 만들거나, 클라우드·데스크톱 예약을 쓰세요.

## cron 식 읽는 법
`CronCreate`는 표준 5칸 cron 식을 씁니다: `분 시 일 월 요일`

| 식 | 뜻 |
|---|---|
| `*/5 * * * *` | 5분마다 |
| `0 * * * *` | 매시 정각 |
| `7 * * * *` | 매시 7분 |
| `0 9 * * *` | 매일 오전 9시 |
| `0 9 * * 1-5` | 평일 오전 9시 |
| `30 14 15 3 *` | 3월 15일 오후 2시 30분 |

- `*`은 "모두", `*/15`는 "15 간격", `1-5`는 "1부터 5까지", `1,15,30`은 "나열한 값"
- 요일은 `0` 또는 `7`이 일요일, `6`이 토요일
- `L`, `W`, `?`, `MON` 같은 이름 표기는 **지원하지 않습니다**
- 일(日)과 요일을 **둘 다** 지정하면 **둘 중 하나만 맞아도** 실행됩니다

## 한계
- 작업은 **Claude Code가 켜져 있고 쉬는 중일 때만** 실행됩니다. 터미널을 닫으면 멈춥니다
- **놓친 실행을 만회하지 않습니다.** 긴 작업 중에 시각이 지났다면 쉬는 순간 **한 번만** 실행됩니다
- `claude --resume`·`--continue`로 이어 가면 `CronCreate` 작업은 복원되지만, **만료된 작업과 시각이 지난 일회성 작업**은 제외됩니다. Claude가 간격을 정하는 `/loop`는 복원되지 않으니 `/loop`를 다시 실행하세요
- 전체를 끄려면 환경 변수 `CLAUDE_CODE_DISABLE_CRON=1`을 설정합니다

## 컴퓨터가 꺼져 있어도 돌려야 한다면
| 방법 | 설명 |
|---|---|
| **클라우드 예약(루틴)** | 클라우드에서 일정·API 호출·GitHub 이벤트로 실행 |
| **GitHub Actions** | CI의 `schedule` 트리거 → [GitHub Actions·CI 연동](#/level3/github-actions) |
| **데스크톱 예약** | 내 컴퓨터에서 로컬 실행 |
| **Windows 작업 스케줄러 + `claude -p`** | 운영체제의 예약 기능으로 [헤드리스 모드](#/level3/headless) 명령을 실행 (공식 기능이 아닌 일반적인 조합입니다) |

> 사람이 없는 예약 실행은 **권한을 물어볼 수 없습니다.** 헤드리스의 `--allowedTools`나 `--permission-mode`로 허용 범위를 미리 정하세요. 그리고 `--max-budget-usd`로 비용 상한을 걸어 두는 것이 안전합니다.

## 자주 하는 실수
- 고정 간격 루프를 `Esc`로 멈추려 함 → Claude에게 **취소해 달라고 요청**하세요
- 터미널을 닫고 "왜 안 돌지?" → `/loop`는 **세션이 열려 있어야** 합니다
- 7일 뒤 작업이 사라진 것을 모름 → 만료 전에 다시 만들거나 클라우드 예약으로
- 정확한 시각이 필요한데 **정각**으로 예약 → 지터 때문에 어긋날 수 있습니다
- 사용량을 생각하지 않고 **짧은 간격**으로 반복 → 반복마다 사용량이 쌓입니다
