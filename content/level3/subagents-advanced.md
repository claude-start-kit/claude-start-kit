# 서브에이전트 심화

> 2단계에서는 서브에이전트를 **만들고 부르는 법**을 익혔습니다. 이번에는 **도구 제한·모델 지정·권한·기억·격리**를 세밀하게 정하고, 여러 개를 **병렬·연쇄**로 쓰는 방법을 다룹니다. 먼저 [서브에이전트(2단계)](#/level2/subagents)를 읽고 오세요.

## 이 레슨의 구성
1. 파일 구조와 저장 위치(우선순위)
2. 설정 필드 전체 훑기
3. **도구 제한**, **모델**, **권한 모드**
4. **스킬 미리 넣기**, **기억(memory)**, **MCP 한정**, **worktree 격리**
5. 부르는 방법, 포그라운드·백그라운드, 병렬·연쇄, 포크
6. 한계와 문제 해결

## 저장 위치와 우선순위
같은 이름이 여러 곳에 있으면 **위쪽(우선순위 높음)** 것이 쓰입니다.

| 순위 | 위치 | 범위 | 만드는 법 |
|---|---|---|---|
| 1 (최고) | 관리형 설정 | 조직 전체 | 관리자 배포 |
| 2 | `--agents` 옵션 | **이번 세션만** (저장 안 됨) | 시작할 때 JSON으로 전달 |
| 3 | `.claude\agents\` | 이 프로젝트 | Claude에게 요청하거나 파일 작성 |
| 4 | `%USERPROFILE%\.claude\agents\` | 내 모든 프로젝트 | 위와 같음 |
| 5 (최저) | 플러그인의 `agents\` | 플러그인을 켠 곳 | [플러그인](#/level3/plugins) 설치 |

- **프로젝트 서브에이전트**는 git에 커밋해 팀이 같이 쓰고 개선합니다
- 현재 폴더에서 저장소 루트까지 **올라가며** 모든 `.claude\agents\`를 찾고, 이름이 겹치면 **작업 폴더에 가장 가까운 것**을 씁니다
- 하위 폴더(`agents\review\` 등)로 나눠도 되지만 정체성은 **파일 안의 `name`** 으로만 정해지므로 폴더가 달라도 **이름은 겹치지 않게** 하세요
- 플러그인 서브에이전트는 폴더 경로가 이름에 붙습니다: `agents\review\security.md` → `my-plugin:review:security`

## 설정 필드
frontmatter(`---` 사이)에 씁니다. **`name`과 `description`만 필수**입니다. 여러 단어 필드는 **camelCase**(`maxTurns`, `disallowedTools`)이며 철자가 다르면 **오류 없이 무시**됩니다.

| 필드 | 설명 |
|---|---|
| `name` | 고유 이름(256자 이하). 맨 앞 `-`·`:` 사용 불가 |
| `description` | **Claude가 언제 맡길지**의 기준 |
| `tools` | 허용할 도구 목록(허용 목록). 생략하면 모두 상속 |
| `disallowedTools` | 뺄 도구(거부 목록) |
| `model` | `sonnet` · `opus` · `haiku` · `fable` · 전체 모델 ID · `inherit` |
| `permissionMode` | `default` · `acceptEdits` · `auto` · `dontAsk` · `bypassPermissions` · `plan` |
| `maxTurns` | 최대 반복 횟수. 넘으면 **부분 결과**로 돌려주고 이어서 시킬 수 있음 |
| `skills` | 시작할 때 **내용을 통째로** 넣어 줄 스킬 |
| `mcpServers` | 이 서브에이전트만 쓸 MCP 서버 |
| `hooks` | 이 서브에이전트에만 적용할 [훅](#/level3/hooks) |
| `memory` | 대화를 넘어 기억을 유지 (`user` · `project` · `local`) |
| `background` | `true`면 항상 백그라운드로 실행 |
| `effort` | 노력도 (`low`~`max`) |
| `isolation` | `worktree`면 임시 git worktree에서 격리 실행 |
| `color` | 목록·기록에서 표시할 색 |
| `omitClaudeMd` | `true`면 `CLAUDE.md` 없이 시작 (위임 프롬프트만으로 충분할 때) |

> 파일이 **로드되지 않는** 흔한 이유: `name`이 없음(문서로 취급됨) · 첫 줄이 `---`가 아님 · `description`이 없음 · YAML 문법 오류. `claude plugin validate .claude\agents`로 점검하거나 `claude --debug`로 로그를 보세요.

## 도구 제한하기
**허용 목록(`tools`)** 은 "이것만", **거부 목록(`disallowedTools`)** 은 "이것만 빼고"입니다. 둘 다 있으면 `disallowedTools`를 먼저 적용합니다.

```markdown
---
name: safe-researcher
description: 제한된 권한으로 조사만 하는 에이전트
tools: Read, Grep, Glob, Bash
---
```
```markdown
---
name: no-writes
description: 파일 쓰기만 뺀 나머지 도구를 상속
disallowedTools: Write, Edit
---
```

> **주의: `Bash`를 허용하면 파일을 바꿀 수 있습니다.** 위 `safe-researcher`는 `Edit`·`Write`가 없어도 `Bash` 명령으로 파일을 고칠 수 있습니다. 진짜 읽기 전용이 필요하면 `Bash`를 빼세요.
>
> `disallowedTools: Bash(git push *)`처럼 조건을 붙여도 **`Bash` 전체가 빠집니다.** 특정 명령만 막으려면 설정의 `permissions.deny`에 `Bash(git push *)`를 넣으세요. 이 규칙은 메인 대화와 서브에이전트에 모두 적용됩니다.

**MCP 도구 한꺼번에 다루기**
| 목적 | 필드 | 항목 예 |
|---|---|---|
| 한 서버의 도구를 모두 허용 | `tools` | `mcp__github__*` |
| 한 서버의 도구를 모두 제거 | `disallowedTools` | `mcp__github` |
| 모든 MCP 도구 제거 | `disallowedTools` | `mcp__*` |

`tools` 목록의 **항목이 하나도 실제 도구로 풀리지 않으면**(전부 철자 오류 등) 서브에이전트가 시작되지 않고 오류를 냅니다.

### 서브에이전트가 못 쓰는 도구
모든 서브에이전트에서 빠지는 도구가 있습니다: 사용자에게 질문하는 도구(`AskUserQuestion`), 플랜 모드 진입·종료 도구, 대화 종료 도구 등. 그리고 **백그라운드**(기본값)로 도는 서브에이전트는 기본 제공 도구 중 **일부만** 씁니다(`Read`, `Grep`, `Glob`, `Bash`, `PowerShell`, `Edit`, `Write`, `WebFetch`, MCP 도구 등은 유지). 목록에 없는 도구를 `tools`에 적어도 소용없습니다.

### 어떤 서브에이전트를 부를 수 있는지 제한
서브에이전트가 **또 다른 서브에이전트를 불러도** 되는지는 `tools`에 `Agent`를 넣느냐 빼느냐로 정합니다. 읽기 전용 검토자라면 `Agent`를 빼세요.

## 모델 고르기
`model`에는 별칭(`sonnet`, `opus`, `haiku`, `fable`), 전체 모델 ID(예: `claude-sonnet-5-5`), 또는 `inherit`(메인 대화의 모델)를 씁니다. 여러 곳에서 정해지면 **위에서부터** 적용됩니다.

1. Claude가 호출할 때 넘기는 **호출별 `model`** (별칭만 가능)
2. 서브에이전트 **정의 파일**의 `model`
3. 환경 변수 `CLAUDE_CODE_SUBAGENT_MODEL`
4. **메인 대화의 모델**

> 정의 파일에 `model`이 없으면 기본적으로 **메인 대화와 같은 모델**입니다. 단순한 조사는 `haiku`로 보내 사용량을 아끼는 식으로 쓰세요.

## 권한 모드
`permissionMode`로 서브에이전트가 **허가를 어떻게 처리할지** 정합니다. 생략하면 메인 대화의 모드를 따릅니다.

| 메인 대화가 | 서브에이전트의 `permissionMode` |
|---|---|
| `bypassPermissions`, `acceptEdits`, `auto` | **무시됨** — 메인과 같은 모드로 실행 |
| `plan` | **무시됨** — 계속 플랜 모드 |
| `default`, `dontAsk` | **설정한 값**이 적용 (단, `bypassPermissions`는 메인이 그 모드일 때만) |

| 모드 | 동작 |
|---|---|
| `default` | 허가를 물음 |
| `acceptEdits` | 작업 폴더 안 파일 수정과 흔한 파일 명령을 자동 허용 |
| `auto` | 분류기가 대부분의 동작을 검토 |
| `dontAsk` | 물어봐야 하는 호출은 자동 **거부** (명시적으로 허용한 도구는 동작) |
| `bypassPermissions` | 허가 확인을 건너뜀 (메인이 이 모드일 때만) |
| `plan` | 읽기 전용 탐색 |

> 플러그인에서 온 서브에이전트는 `permissionMode`, `mcpServers`, `hooks`가 **무시**됩니다. 보안상 플러그인이 권한을 넓히지 못하게 하기 위해서입니다.

## 스킬 미리 넣기
`skills`에 적은 스킬은 **시작할 때 본문 전체**가 서브에이전트의 컨텍스트에 들어갑니다.
```markdown
---
name: api-developer
description: 팀 규칙에 따라 API 엔드포인트를 구현
skills:
  - api-conventions
  - error-handling-patterns
---
미리 로드된 스킬의 규칙과 패턴을 따라 API 엔드포인트를 구현하세요.
```
- 이 필드는 **무엇을 미리 로드할지**만 정하며, 접근 자체를 막지는 않습니다 (실행 중에도 `Skill` 도구로 다른 스킬을 찾아 쓸 수 있음)
- `disable-model-invocation: true`인 스킬은 **미리 넣을 수 없습니다**
- 반대 방향도 있습니다: 스킬의 `context: fork`는 "스킬을 서브에이전트에서 실행"합니다 ([스킬](#/level3/skills))

## 기억 유지하기 (memory)
`memory`를 켜면 서브에이전트가 **대화가 끝나도 남는 폴더**에 배운 것을 쌓아 갑니다. (내 선호, 받은 교정, 프로젝트 결정 등)
```markdown
---
name: code-reviewer
description: 코드 품질과 모범 사례를 검토
memory: project
---
당신은 코드 리뷰어입니다. 검토하면서 받은 선호와 교정을 에이전트 기억에 계속 갱신하세요.
```
| 범위 | 위치 | 쓰는 때 |
|---|---|---|
| `user` | `%USERPROFILE%\.claude\agent-memory\<이름>\` | **모든 프로젝트**에서 기억 |
| `project` | `.claude\agent-memory\<이름>\` | 프로젝트 전용, **git으로 공유** (권장 기본값) |
| `local` | `.claude\agent-memory-local\<이름>\` | 프로젝트 전용, **커밋 안 함** |

- 켜면 `MEMORY.md`의 앞부분(200줄 또는 25KB)이 시스템 프롬프트에 들어가고, 읽기·쓰기·편집 도구가 **자동으로 켜집니다**
- 자동 메모리 기능을 끄면 `memory` 필드도 **효과가 없습니다**
- 팁: "작업 전에 기억을 확인해", "끝나면 배운 것을 기억에 저장해"라고 요청하거나, 지침을 서브에이전트 파일에 직접 적어 두세요

## MCP 서버를 서브에이전트에만 연결하기
메인 대화에는 필요 없는 MCP 서버를 **이 서브에이전트에게만** 줄 수 있습니다. 서버의 도구 설명이 메인 컨텍스트를 차지하지 않는 장점이 있습니다.
```markdown
---
name: browser-tester
description: Playwright로 실제 브라우저에서 기능을 시험
mcpServers:
  - playwright:
      type: stdio
      command: npx
      args: ["-y", "@playwright/mcp@latest"]
  - github
---
Playwright 도구로 페이지를 열고 스크린샷을 찍고 조작하세요.
```
- **인라인 정의**(이름: 설정)는 이 서브에이전트가 **시작될 때 연결**되고 끝나면 **해제**됩니다
- **이름만 적은 항목**(`github`)은 이미 설정된 서버의 연결을 **공유**합니다
- 프로젝트의 `.claude\agents\` 파일에 든 인라인 서버는 **폴더를 신뢰한 뒤에야** 로드됩니다
- 조직 정책(허용·차단 목록)은 여기에도 적용됩니다

## 격리해서 실행하기: worktree
`isolation: worktree`를 넣으면 서브에이전트가 **임시 git worktree**(저장소의 독립된 작업 복사본)에서 일합니다. 내 작업 폴더를 건드리지 않고 시도할 수 있습니다.
- 기본 브랜치에서 갈라져 나옵니다 (부모 세션의 `HEAD`가 아님)
- **변경이 없으면 자동으로 정리**됩니다
- 개념은 [Git worktree](#/level2/git-branch-worktree)를 참고하세요

## 훅으로 조건부 규칙 걸기
서브에이전트 파일의 `hooks`로 **그 서브에이전트가 일하는 동안만** 적용되는 규칙을 둘 수 있습니다. 예를 들어 DB 쿼리 서브에이전트가 `SELECT`만 쓰게 `PreToolUse` 훅으로 검증하는 방식입니다. 프로젝트 설정 파일에서 `SubagentStart`·`SubagentStop` 이벤트에 훅을 걸 수도 있습니다. ([훅](#/level3/hooks))

## 서브에이전트 부르기
네 가지 방법이 있고, 아래로 갈수록 더 강하게 지정합니다.

| 방법 | 예 | 효과 |
|---|---|---|
| **자동 위임** | (아무것도 안 함) | Claude가 `description`과 요청을 보고 판단 |
| **말로 지정** | `test-runner 서브에이전트로 실패하는 테스트를 고쳐 줘` | Claude가 위임 여부를 판단 |
| **@멘션** | `@"code-reviewer (agent)" 인증 변경 부분을 봐 줘` | **이번 작업은 이 서브에이전트가** |
| **세션 전체** | `claude --agent code-reviewer` | 메인 스레드 자체가 그 서브에이전트의 도구 제한·모델로 동작 |

- `@`를 입력하면 목록에서 고를 수 있습니다. 직접 쓰려면 `@agent-이름`
- 플러그인 서브에이전트는 `플러그인:이름` 형태입니다 (`claude --agent my-plugin:security-reviewer`)
- **항상** 쓰게 하려면 `.claude\settings.json`에 `"agent": "code-reviewer"`. 명령줄 옵션이 설정보다 우선합니다
- `--agent`를 쓰면 서브에이전트의 **프롬프트가 기본 시스템 프롬프트를 대체**합니다. `CLAUDE.md`는 그대로 로드됩니다
- **자동 위임을 더 잘 되게 하려면** `description`에 "사용자가 코드를 수정한 직후에 **적극적으로** 사용" 같은 문구를 넣으세요
- 서브에이전트 설명이 **너무 길면**(전체 15,000토큰 초과) 시작 시 경고가 나옵니다. 설명은 짧게 쓰세요

## 포그라운드와 백그라운드
| | 포그라운드 | 백그라운드 |
|---|---|---|
| 메인 대화 | **끝날 때까지 멈춤** | **계속 작업 가능** |
| 허가 질문 | 바로 나에게 | 메인 세션에 **서브에이전트 이름과 함께** 표시. 승인하거나 `Esc`로 그 호출만 거부 |
| 도구 | 전체 | 일부만 |

- 별다른 설정이 없으면 Claude가 메인 대화에서 시작하는 서브에이전트는 **백그라운드**로 시작됩니다
- 진행 중인 것은 `/tasks`로 보고, 끝난 서브에이전트의 기록도 잠시 열어 볼 수 있습니다 (끝난 뒤 약 30초)
- 백그라운드 서브에이전트의 허가를 **"세션 내내 허용"** 으로 답하면 **메인 대화까지** 그 허용이 적용됩니다. 신중하게 고르세요
- Claude가 결과를 **기다리게** 하려면 환경 변수 `CLAUDE_CODE_FORK_SUBAGENT`를 `0`으로 설정해 포크 모드를 끄고 "리뷰어를 실행하고 보고서를 기다려"라고 요청합니다. 기다리는 도중에 계속 일하려면 `Ctrl+B`

## 자주 쓰는 활용 패턴
**1. 출력이 많은 작업 격리하기** — 테스트·로그·문서 조회는 출력이 길어 메인 컨텍스트를 채웁니다.
```text
서브에이전트로 테스트 스위트를 실행하고, 실패한 테스트와 오류 메시지만 보고해 줘
```

**2. 병렬 조사** — 서로 독립된 조사를 동시에 시킵니다.
```text
인증, 데이터베이스, API 모듈을 각각 별도의 서브에이전트로 병렬 조사해 줘
```
> 서브에이전트가 많으면 **각자 토큰을 쓰고** 결과가 메인 대화로 돌아와 컨텍스트도 늘어납니다. 오래 병렬로 돌릴 일이면 별도 세션을 쓰는 편이 낫습니다.

**3. 연쇄** — 앞 결과를 다음 서브에이전트에 넘깁니다.
```text
code-reviewer로 성능 문제를 찾고, 그다음 optimizer로 고쳐 줘
```

### 서브에이전트 vs 메인 대화
| 메인 대화가 낫다 | 서브에이전트가 낫다 |
|---|---|
| 자주 주고받으며 다듬는 일 | **출력이 많고** 요약만 필요한 일 |
| 계획·구현·테스트가 **맥락을 공유** | **도구 제한·권한**을 강제하고 싶을 때 |
| 작고 빠른 수정 | 독립적으로 끝낼 수 있는 일 |
| 지연이 중요 (새 서브에이전트는 맥락을 새로 모아야 함) | |

이미 대화에 있는 내용을 **잠깐 물어볼** 때는 서브에이전트 대신 `/btw`를 쓰면 기록에 남지 않습니다. 같은 절차를 메인 대화 안에서 재사용하려면 [스킬](#/level3/skills)이 낫습니다.

## 포크: 지금까지의 대화를 물려받는 서브에이전트
**포크**는 새로 시작하지 않고 **지금까지의 대화 전체**를 물려받는 서브에이전트입니다. 배경 설명이 너무 길 때, 또는 같은 출발점에서 **여러 접근을 동시에 시도**할 때 씁니다.

```text
/subtask 지금까지의 파서 변경에 대한 단위 테스트를 작성해 줘
```
- 포크의 도구 호출은 부모 대화에 남지 않고 **최종 결과만** 돌아옵니다
- 프롬프트 캐시를 부모와 공유해서 새 서브에이전트보다 **비용이 낮습니다**
- 프롬프트 아래 패널에 표시되며 `↑↓`로 이동, `Enter`로 기록 열기·후속 메시지, `x`로 중지
- **포크는 포크를 만들 수 없습니다**

| | 포크 | 일반 서브에이전트 |
|---|---|---|
| 컨텍스트 | 대화 **전체** 물려받음 | 내가 넘긴 프롬프트만 |
| 시스템 프롬프트·도구 | 부모와 **동일** | 정의 파일 기준 |
| 모델 | 부모와 같음 | 모델 규칙에 따름 |

포크를 막으려면 설정의 `permissions.deny`에 `"Agent(fork)"`를 넣거나 `CLAUDE_CODE_FORK_SUBAGENT=0`.

## 서브에이전트의 서브에이전트, 이어서 시키기
- **중첩**: 기본적으로 메인 아래 **최대 3단계**까지 서브에이전트가 또 서브에이전트를 부를 수 있습니다. 환경 변수 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`로 바꾸고 `1`이면 중첩이 꺼집니다
- **동시 실행 한도**: 한 세션에서 기본 **20개**까지. 넘으면 `Concurrent subagent limit reached` 오류가 나며 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`로 조정합니다
- **이어서 시키기(resume)**: 서브에이전트를 부를 때마다 **새 인스턴스**가 생깁니다. 이전 작업을 이어 가려면 Claude에게 "방금 코드 리뷰를 이어서 인가 로직도 분석해 줘"라고 하세요. 대화 기록이 그대로 유지됩니다. 이어 갈 일이 있다면 내장 Explore·Plan보다 `general-purpose`나 **직접 만든** 서브에이전트가 낫습니다

## 예시: 코드 리뷰어
```markdown
---
name: code-reviewer
description: 코드 리뷰 전문가. 코드 품질·보안·유지보수성을 검토합니다. 코드를 작성하거나 수정한 직후 바로 사용하세요.
tools: Read, Grep, Glob, Bash
model: inherit
---
당신은 높은 기준을 지키는 시니어 코드 리뷰어입니다.

호출되면:
1. git diff로 최근 변경을 확인합니다
2. 수정된 파일에 집중합니다
3. 바로 검토를 시작합니다

검토 체크리스트:
- 코드가 명확하고 읽기 쉬운가
- 함수·변수 이름이 좋은가
- 중복 코드가 없는가
- 오류 처리가 적절한가
- 노출된 비밀 값·API 키가 없는가
- 입력 검증이 되어 있는가
- 테스트 범위는 충분한가

우선순위별로 피드백하세요:
- 반드시 고칠 것 (치명적)
- 고치는 것이 좋은 것 (경고)
- 개선 제안

고치는 방법의 구체적인 예를 포함하세요.
```
> 이 예시는 `Edit`·`Write`가 없지만 `Bash`가 있어 **파일을 바꿀 수는 있습니다.** 정말 수정을 막으려면 `Bash`도 빼고 `git diff`는 메인 대화에서 받아 넘기세요.

## 문제 해결
| 증상 | 확인할 것 |
|---|---|
| 서브에이전트가 목록에 없음 | 파일이 `.claude\agents\`에 있는지, `name`·`description`이 있는지, 첫 줄이 `---`인지 |
| 설정이 **안 먹힘** | `camelCase` 철자 (`maxTurns` 등). `claude --debug` 로그에서 `does not recognize or apply` 검색 |
| 시작 즉시 오류 | `tools`의 항목이 전부 풀리지 않음 (철자·사용 불가 도구) |
| 자주 안 불린다 | `description`을 구체적으로, "적극적으로 사용" 문구 추가 |
| 허가 질문이 너무 많다 | `permissionMode`와 메인 대화의 모드 관계 확인 (메인이 `default`일 때만 값이 적용됨) |
| 서브에이전트가 고친 파일을 되돌리고 싶다 | 백그라운드에서 일한 서브에이전트의 수정은 `/rewind`(체크포인트)로 **복원되지 않을 수 있습니다.** **worktree 격리**나 git을 쓰세요 |

## 확인 체크
- [ ] `tools` 또는 `disallowedTools`로 도구를 제한한 서브에이전트를 만들었다
- [ ] `model`을 `haiku`로 지정해 가벼운 일을 맡겨 봤다
- [ ] `@멘션`으로 직접 불러 봤다
- [ ] `/tasks`로 실행 중인 서브에이전트를 확인했다

## 자주 하는 실수
- `Bash`를 허용하고 **"읽기 전용"** 이라고 믿음 → 명령으로 파일을 바꿀 수 있습니다
- `disallowedTools: Bash(git push *)`로 **특정 명령만** 막으려 함 → `Bash` 전체가 빠집니다. `permissions.deny`를 쓰세요
- 필드 이름을 `max_turns`처럼 **snake_case**로 씀 → 조용히 무시됩니다
- 서브에이전트를 **너무 많이** 병렬로 돌림 → 토큰이 각자 소모되고 결과가 컨텍스트에 쌓입니다
- 플러그인 서브에이전트에 `permissionMode`·`hooks`를 넣고 효과를 기대 → 무시됩니다
