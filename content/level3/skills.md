# 스킬(Skills)과 커스텀 명령

> **스킬**은 반복하는 **작업 절차를 파일 하나에 적어 두고**, `/이름`으로 부르거나 Claude가 필요할 때 알아서 꺼내 쓰게 하는 기능입니다. 같은 지침을 채팅에 계속 붙여넣고 있다면 스킬로 만들 때입니다.

## 스킬이 필요한 순간
- 같은 체크리스트·절차를 **매번 다시 붙여넣을 때**
- `CLAUDE.md`의 한 부분이 사실이 아니라 **절차**로 길어졌을 때

| | `CLAUDE.md` | 스킬 |
|---|---|---|
| 불러오는 시점 | **항상** 컨텍스트에 있음 | **쓸 때만** 본문이 로드됨 |
| 알맞은 내용 | 프로젝트 규칙·사실 | 단계가 있는 **작업 절차**, 긴 참고 자료 |
| 비용 | 길수록 매번 부담 | 쓰기 전까지는 거의 없음 (설명 한 줄만 목록에 있음) |

> **커스텀 명령은 스킬에 합쳐졌습니다.** 예전 방식인 `.claude\commands\이름.md` 파일도 **그대로 동작**합니다. 새로 만든다면 스킬 방식(폴더)을 권장합니다. 보조 파일(스크립트 등)을 둘 수 있기 때문입니다.

## 이미 들어 있는 스킬
Claude Code에는 기본 제공 스킬이 있습니다: `/doctor`, `/code-review`, `/batch`, `/debug`, `/loop`, `/claude-api` 등. 전체 목록은 [슬래시 명령어 전체 보기](#/ref/slash-all)에서 **Skill**로 표시된 항목입니다.

| 스킬 | 용도 |
|---|---|
| `/doctor` | 설치·설정·`CLAUDE.md`·확장 점검 (고치기 전에 먼저 보고하고 확인을 받음) |
| `/run` · `/verify` | 앱을 실제로 실행해 변경이 동작하는지 확인 |
| `/loop` | 반복 실행 ([예약 작업](#/level3/scheduled)) |

## 첫 스킬 만들기
**"커밋 안 한 변경을 요약하고 위험한 부분을 알려 주는"** 스킬입니다.

**1. 폴더 만들기** — 개인 스킬 폴더에 만들면 **내 모든 프로젝트**에서 씁니다.
```powershell
mkdir $env:USERPROFILE\.claude\skills\summarize-changes
```

**2. `SKILL.md` 작성** — 위 폴더 안에 `SKILL.md`라는 이름으로 저장합니다.
```markdown
---
description: 커밋하지 않은 변경을 요약하고 위험한 부분을 알려 줍니다. 무엇이 바뀌었는지 묻거나, 커밋 메시지가 필요하거나, diff를 검토하고 싶을 때 사용
---

## 현재 변경 사항

!`git diff HEAD`

## 지침

위 변경을 2~3개의 항목으로 요약하고, 오류 처리 누락·하드코딩된 값·고쳐야 할 테스트 같은
위험한 부분을 알려 주세요. diff가 비어 있으면 커밋하지 않은 변경이 없다고 알려 주세요.
```

**3. 시험하기** — git 프로젝트에서 파일을 조금 고치고 `claude`를 실행한 뒤 두 가지 방법으로 불러 보세요.
```text
내가 뭘 바꿨지?
```
```text
/summarize-changes
```
앞의 방법은 **Claude가 설명을 보고 알아서** 꺼내 쓰는 것이고, 뒤는 **직접 호출**입니다.

<details>
<summary>예시 읽는 법</summary>

| 항목 | 쉬운 설명 |
|---|---|
| `---` 사이의 부분 | **frontmatter**. 스킬의 이름표·설정입니다. 파일 **첫 줄**이 `---`여야 인식됩니다 |
| `description` | **무엇을 하고 언제 쓰는지.** Claude가 이걸 읽고 스킬을 쓸지 판단합니다. 사용자가 실제로 할 법한 말을 넣으세요 |
| `---` 아래 본문 | 스킬이 실행될 때 Claude가 따르는 지침입니다 |
| `` !`git diff HEAD` `` | **동적 컨텍스트 주입.** Claude가 읽기 **전에** 이 명령을 실행해 출력으로 바꿔 넣습니다. 그래서 Claude가 추측이 아니라 **지금의 실제 변경**을 보고 답합니다 |
| 폴더 이름 `summarize-changes` | `/summarize-changes`라는 **명령 이름**이 됩니다 (`name`을 따로 쓰면 그 값) |

> `` !`명령` `` 은 줄 **맨 앞이나 공백 바로 뒤**에 있어야 인식됩니다. 여러 줄 명령은 ` ```! ` 코드 블록으로 씁니다. Windows에서 PowerShell로 실행하려면 frontmatter에 `shell: powershell`을 넣습니다.

</details>

## 스킬은 어디에 두나
| 위치 | 경로 | 적용 범위 |
|---|---|---|
| 개인 | `%USERPROFILE%\.claude\skills\이름\SKILL.md` | 내 모든 프로젝트 |
| 프로젝트 | `.claude\skills\이름\SKILL.md` | 이 저장소 (**git에 커밋**하면 팀 전체가 씀) |
| 하위 폴더 | `하위폴더\.claude\skills\이름\SKILL.md` | 그 폴더 안에서 작업할 때 |
| 플러그인 | 플러그인의 `skills\이름\SKILL.md` | 플러그인을 켠 곳. 명령은 `/플러그인:이름` |
| 조직(엔터프라이즈) | 관리형 설정 폴더 | 조직 전체 |

이름이 같은 스킬이 여러 곳에 있으면 **엔터프라이즈 → 개인 → 프로젝트** 순으로 우선합니다. (플러그인 스킬은 이름에 접두사가 붙어 충돌하지 않습니다.)

> 스킬 폴더 이름에 **공백·특수문자·`<` `>`** 를 쓰지 마세요. 이름이 거부되면 스킬이 로드되지 않습니다. 영문 소문자와 하이픈을 권장합니다.

## 스킬 종류 두 가지
**참고형** — Claude가 작업하면서 **같이 참고하는 지식**(규칙·패턴·스타일 가이드).
```markdown
---
name: api-conventions
description: 이 코드베이스의 API 설계 규칙
---
API 엔드포인트를 만들 때:
- RESTful 이름 규칙을 따른다
- 오류 형식을 일관되게 반환한다
- 요청 값을 검증한다
```

**작업형** — 배포·커밋처럼 **단계별로 실행하는 행동.** 보통 `/이름`으로 직접 부르고, Claude가 멋대로 실행하지 못하게 막습니다.
```markdown
---
name: deploy
description: 애플리케이션을 운영 환경에 배포
disable-model-invocation: true
---
$ARGUMENTS를 운영에 배포합니다:
1. 테스트를 실행한다
2. 빌드한다
3. 배포 대상에 올린다
4. 배포가 성공했는지 확인한다
```
실행: `/deploy staging` — 뒤에 쓴 `staging`이 `$ARGUMENTS`로 들어갑니다.

## frontmatter 주요 필드
모든 필드는 선택이고, **`description`만 권장**됩니다. 철자가 틀린 필드는 **오류 없이 무시**됩니다.

| 필드 | 설명 |
|---|---|
| `name` | `/` 메뉴에 보이는 명령 이름. 생략하면 폴더 이름 |
| `description` | 무엇을 하고 언제 쓰는지. **핵심 용도를 앞에** 쓰세요 (`when_to_use`와 합쳐 1,536자까지만 목록에 표시) |
| `when_to_use` | 부르는 말·요청 예시 같은 추가 설명 |
| `argument-hint` | 자동완성에 표시할 인자 안내. 예: `[이슈 번호]` |
| `disable-model-invocation` | `true`면 **Claude가 스스로 실행하지 못함**. 부작용이 있는 작업용 |
| `user-invocable` | `false`면 **내가 `/`로 부를 수 없고** Claude만 씀. 배경 지식용 |
| `allowed-tools` | 이 스킬이 실행되는 **그 턴 동안** 허가 없이 쓸 도구 |
| `model` | 이 스킬이 켜진 동안 쓸 모델 (`inherit`면 유지) |
| `effort` | 이 턴의 노력도 |
| `context: fork` | **서브에이전트에서** 실행 (메인 대화를 어지럽히지 않음) |
| `agent` | `context: fork`일 때 쓸 서브에이전트 종류 |
| `hooks` | 이 스킬이 실행될 때 등록할 [훅](#/level3/hooks) |
| `paths` | 이 파일 패턴을 다룰 때만 활성화 |
| `shell` | `` !`명령` `` 을 실행할 셸 (`bash` 기본, `powershell`) |

### 누가 부를 수 있나 (두 필드 조합)
| 설정 | 내가 부름 | Claude가 부름 | 설명이 컨텍스트에 |
|---|---|---|---|
| (기본) | 예 | 예 | 있음 |
| `disable-model-invocation: true` | 예 | **아니오** | **없음** |
| `user-invocable: false` | **아니오** | 예 | 있음 |

> `/deploy`처럼 **되돌리기 어려운 일**은 `disable-model-invocation: true`로 막아 두세요. 코드가 준비돼 보인다고 Claude가 알아서 배포하면 안 되기 때문입니다.
>
> 직접 실행하려면 **메시지의 맨 앞**에 `/이름`을 쓰세요. 문장 중간에 쓰면 "이 스킬을 써도 좋다"는 **허락**일 뿐 바로 실행되지는 않습니다.

## 인자와 변수
| 변수 | 의미 |
|---|---|
| `$ARGUMENTS` | 호출할 때 뒤에 쓴 **전체 인자** |
| `$0`, `$1` … | 인자를 **순서대로** (0부터). 공백이 든 값은 따옴표로 묶기: `/my-skill "hello world" second` |
| `$이름` | `arguments: [issue, branch]`처럼 선언한 이름 |
| `${CLAUDE_SESSION_ID}` | 현재 세션 ID |
| `${CLAUDE_SKILL_DIR}` | 이 스킬의 `SKILL.md`가 있는 폴더 (함께 둔 스크립트 호출용) |
| `${CLAUDE_PROJECT_DIR}` | 프로젝트 루트 |

인자 값에 `$1` 같은 글자가 들어 있어도 **확장되지 않고 그대로** 들어갑니다. 글자 그대로 `$1.00`을 쓰려면 `\$1.00`.

## 도구 미리 허가하기
```markdown
---
name: commit
description: 현재 변경을 스테이징하고 커밋
disable-model-invocation: true
allowed-tools: Bash(git add *) Bash(git commit *) Bash(git status *)
---
```
이 스킬이 실행되는 동안 위 git 명령은 **허가를 묻지 않습니다.** 허가는 **다음 메시지를 보내면 사라집니다.** 도구를 **제한**하는 기능은 아닙니다. 다른 도구도 평소처럼 쓸 수 있습니다.

> 남이 만든 저장소의 `.claude\skills\`는 **`allowed-tools`를 먼저 읽어 보세요.** 스킬이 스스로에게 넓은 권한을 줄 수 있습니다.

## 파일 여러 개로 나누기
긴 참고 자료는 따로 두면 필요할 때만 읽힙니다.
```text
my-skill/
├── SKILL.md          필수. 개요와 안내
├── reference.md      자세한 자료 (필요할 때 로드)
├── examples.md       사용 예시
└── scripts/
    └── helper.py     실행만 되고 로드되지는 않음
```
`SKILL.md`에서 각 파일이 **무엇이고 언제 읽는지** 적어 주세요. 본문은 **500줄 안쪽**으로 유지합니다.

## 서브에이전트에서 실행하기
`context: fork`를 넣으면 스킬이 **별도의 서브에이전트**에서 돌아 결과 요약만 돌아옵니다. 긴 조사에 좋습니다. ([서브에이전트](#/level2/subagents))
```markdown
---
name: pr-summary
description: Pull Request 변경 내용을 요약
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---
## PR 정보
- 변경 내용: !`gh pr diff`
- 댓글: !`gh pr view --comments`
- 바뀐 파일: !`gh pr diff --name-only`

## 할 일
이 PR을 요약해 주세요...
```

## 스킬이 컨텍스트에서 지내는 방식
- 스킬을 부르면 본문이 대화에 **한 번 들어가고 이후 턴에도 남습니다.** 파일을 다시 읽지 않습니다
- 그래서 본문의 **모든 줄이 계속 토큰 비용**입니다. 짧고 지시형으로 쓰세요 ("무엇을 하라"만, 이유 설명은 최소로)
- 지침은 **작업 전체에 적용되게** 쓰세요. "테스트를 실행해"보다 "수정할 때마다 테스트를 실행해"
- 대화가 **압축(컴팩트)** 되면 스킬 앞부분만 남을 수 있으니 **가장 중요한 지침을 위쪽에** 두세요. 필요하면 다시 호출하세요

## 문제 해결
| 증상 | 확인할 것 |
|---|---|
| 스킬이 **안 불린다** | `description`에 사용자가 쓸 법한 **말**이 있는지 / "사용 가능한 스킬이 뭐야?"로 목록에 있는지 / `/이름`으로 직접 호출 / frontmatter YAML 오류는 `claude --debug`로 확인 |
| **너무 자주** 불린다 | `description`을 더 구체적으로, 또는 `disable-model-invocation: true` |
| 처음엔 따르다가 **나중에 무시** | 반드시 지켜야 하는 규칙은 스킬이 아니라 **[훅](#/level3/hooks)** 으로. 판단이 필요한 지침은 작업 전체에 적용되게 다시 쓰기 |
| 설명이 잘림 | 스킬이 많으면 목록 예산을 넘어 일부 설명이 줄어듭니다. `/doctor`로 비용 확인 |
| `<`, `>`가 `&lt;` `&gt;`로 보임 | `description`에서는 `[브랜치]`처럼 **대괄호**를 쓰거나 `argument-hint`로 옮기기 |

## 스킬 직접 쓰기보다 쉬운 방법
Claude에게 만들어 달라고 하세요.
```text
내가 자주 하는 "릴리스 노트 작성" 절차를 스킬로 만들어 줘.
개인 스킬 폴더에 SKILL.md로 저장하고, 내가 직접 /release-notes로만 실행되게 해 줘.
```

## 확인 체크
- [ ] `%USERPROFILE%\.claude\skills\` 아래에 스킬 폴더와 `SKILL.md`를 만들었다
- [ ] `/스킬이름`으로 **직접** 불러 봤다
- [ ] 말로 요청해 Claude가 **스스로** 꺼내 쓰는지 확인했다
- [ ] 부작용이 있는 스킬에는 `disable-model-invocation: true`를 넣었다

## 자주 하는 실수
- `SKILL.md`의 첫 줄이 `---`가 아님 → frontmatter가 인식되지 않고 **전체가 본문**이 됩니다
- `description`이 **모호함** → Claude가 언제 쓸지 모릅니다. 실제로 할 법한 말을 넣으세요
- 필드 철자 오류(`disable_model_invocation` 등) → 오류 없이 **조용히 무시**됩니다. 하이픈을 쓰세요
- 본문을 **너무 길게** 씀 → 불러올 때마다 토큰이 큽니다. 긴 자료는 파일을 나누세요
- 스킬 폴더 이름에 **특수문자·공백** → 스킬이 로드되지 않습니다
- 비밀번호·키를 스킬에 적음 → 저장소에 올리면 **노출**됩니다
