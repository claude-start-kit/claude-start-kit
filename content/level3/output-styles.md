# 출력 스타일

> **출력 스타일**은 Claude의 **역할·말투·응답 형식**을 세션 내내 바꾸는 지침 묶음입니다. "더 짧게", "이유도 설명해 줘", "묻지 말고 먼저 진행해"를 **매 프롬프트마다 반복하지 않아도** 됩니다.

> 출력 스타일은 Claude가 **따르려 노력하는 지침**일 뿐 **보장은 아닙니다.** 프로젝트에 대해 알려 주는 것은 [`CLAUDE.md`](#/level2/init-claudemd), **반드시 매번 일어나야 하는 일**은 [훅](#/level3/hooks)이 맞습니다.

## 기본 제공 스타일
Claude Code는 **Default** 스타일(소프트웨어 개발용 표준 지침)로 시작합니다. 나머지 네 가지는 이 지침을 **유지한 채** 자기 지침을 **더합니다.**

| 스타일 | 달라지는 점 | 이럴 때 |
|---|---|---|
| **Proactive** | 일을 받으면 **바로 시작**하고 **일상적인 결정은 묻지 않고** 합리적으로 가정 | 틀리면 내가 고칠 테니 계속 진행해 주길 바랄 때 |
| **Concise** | 결과를 **첫 문장**에, 서두·과정 설명·마무리 요약 생략 | 기본 응답이 너무 길 때 |
| **Explanatory** | 코드 선택의 이유를 **`Insight` 블록**으로 짧게 덧붙임 | 코드베이스를 익히는 중이거나 이유까지 알고 싶을 때 |
| **Learning** | Explanatory + 작은 코드 조각을 **내가 직접 쓰도록** 남김 | 일도 끝내면서 **직접 코딩 연습**도 하고 싶을 때 |

### Default
스타일을 고르지 않은 상태입니다. 목록에 `default`로 나오며 다른 스타일처럼 고릅니다.

### Proactive
- 작업을 받으면 **곧바로 구현을 시작**하고 일상적인 결정은 물어보지 않으며, 계획을 **요청하지 않으면** 플랜 모드로 가지 않습니다. 언제든 방향을 바꿀 수 있습니다
- 단, 데이터를 **삭제**하거나 **공유·운영 시스템을 바꾸는** 행동 전에는 대화에서 먼저 확인하라는 지침이 들어 있습니다. 이는 Claude가 따르는 **지침**이며 권한 확인창과는 **별개**입니다
- **권한 모드는 바뀌지 않습니다.** 어떤 도구 호출이 묻지 않고 실행되는지는 여전히 권한 모드가 정합니다

### Concise
- 응답의 **첫 문장**에 일어난 일이나 답을 씁니다. 서두·단계별 설명·마무리 요약을 빼고 단순한 질문은 **한~세 문장**으로 답합니다. 개발 작업 자체는 Default만큼 꼼꼼히 합니다
- 다음 경우에는 **여전히 길게** 씁니다: 내가 **설명을 요청**했을 때, **안전하게 행동하는 데 필요한** 내용(오류 보고, 실패한 테스트 출력, 보안 경고, 삭제 같은 위험 작업의 확인)

### Explanatory
작업은 Default처럼 하고, **왜 그렇게 했는지**를 코드 앞뒤에 `Insight` 블록으로 덧붙입니다. 예:
```text
★ Insight ─────────────────────────────────────
- 이 저장소의 모든 경로는 withAuth 래퍼를 거치므로, 새 엔드포인트도 별도 미들웨어 없이 세션 검사를 받습니다.
- 요청 제한은 limits.ts에서 경로별로 정하기 때문에 이번 변경은 전역 기본값이 아니라 항목을 추가했습니다.
─────────────────────────────────────────────────
```

### Learning
`Insight` 블록에 더해 **내가 코드를 직접 쓰게** 합니다. 일상적인 구현은 Claude가 하고, 오류 처리·자료 구조·비즈니스 로직처럼 **설계 판단이 있는 부분**은 몇 줄을 남깁니다.
- 파일에 `TODO(human)` 주석으로 자리를 표시하고
- 무엇이 만들어졌고, 무엇을 써야 하고, 무엇을 고려할지 요청을 보낸 뒤
- **멈추고 기다립니다.** 내가 코드를 쓰고 끝났다고 알려 주면 코드에 대한 `Insight`를 하나 주고 이어 갑니다

```text
● Learn by Doing
Context: 업로드 폼이 있고 파일을 받기 전에 validateFile()을 부릅니다. 이미지의 크기·형식 검사는 되지만 문서(document) 처리는 아직 없습니다.
Your Task: upload.js의 validateFile() 안에 case "document" 분기를 구현하세요. TODO(human)을 찾으세요.
Guidance: 문서의 크기 제한을 정하고 확장자가 MIME 형식과 일치해야 하는지 결정하세요. {valid: boolean, error?: string}을 반환하세요.
```

## 스타일 바꾸기
선택한 스타일은 **프로젝트의 `.claude\settings.local.json`** 에 저장됩니다.

| 방법 | 설명 |
|---|---|
| **`/output-style 이름`** | 예: `/output-style concise`. 인자 없이 쓰면 **목록과 현재 스타일** 표시. 헤드리스(`-p`)와 Agent SDK 세션에서도 동작 |
| **`/config` → Output style** | 터미널 메뉴에서 선택 |
| VS Code 확장 | `/` 명령 메뉴 → **Output styles** (직접 만든 스타일 포함) |
| 데스크톱 앱 | 설정 파일에 `outputStyle` 직접 입력 |

설정 파일에 직접 쓰려면:
```json
{
  "outputStyle": "Explanatory"
}
```
- **대소문자를 구분합니다.** 기본 제공 이름은 `Proactive`, `Concise`, `Explanatory`, `Learning`으로 씁니다. `explanatory`처럼 틀리면 **Default**가 적용됩니다 (`/output-style` 명령은 대소문자를 무시)
- **모든 프로젝트에서** 기본으로 쓰려면 `%USERPROFILE%\.claude\settings.json`에 `outputStyle`을 둡니다. 프로젝트 설정이 있으면 그쪽이 **우선**합니다
- 세션 중에 바꾸면 **다음 메시지부터** 적용됩니다 (프롬프트 캐시 비용이 첫 메시지에 한 번 듭니다)

## 나만의 스타일 만들기
**마크다운 파일 하나**입니다. 맨 위에 설정(frontmatter), 아래에 Claude를 위한 지침을 씁니다.

**1. 파일 저장 위치** — 파일 이름이 스타일 이름이 됩니다 (`name`을 따로 쓰면 그 값).
| 수준 | 경로 |
|---|---|
| 사용자 | `%USERPROFILE%\.claude\output-styles\` |
| 프로젝트 | `.claude\output-styles\` |
| 관리형 정책 | 관리형 설정 폴더 안의 `.claude\output-styles` |

프로젝트 스타일은 작업 폴더에서 저장소 루트 사이의 모든 `.claude\output-styles\`에서 불러오며, 이름이 겹치면 **작업 폴더에 가장 가까운 것**을 씁니다.

**2. frontmatter와 지침 작성**
```markdown
---
name: Diagrams first
description: 모든 설명을 다이어그램으로 시작합니다
keep-coding-instructions: true
---
코드, 구조, 데이터 흐름을 설명할 때는 먼저 구조를 보여 주는 Mermaid 다이어그램으로 시작하고 그다음 글로 설명하세요.

## 다이어그램 규칙

제어 흐름에는 `flowchart TD`, 요청 경로에는 `sequenceDiagram`을 쓰세요. 다이어그램은 노드 15개 이하로 유지하세요.
```

**3. 전환** — `/output-style Diagrams first` 또는 `/config`. 터미널에서는 **시작할 때** 스타일 파일을 읽으므로, 실행 중에 새로 만들거나 고쳤다면 **Claude Code를 다시 시작**해야 반영됩니다.

### frontmatter 필드
모두 선택이며 필드 이름은 소문자와 하이픈입니다. **철자가 틀리면 오류 없이 무시**됩니다. YAML이 깨지면 파일 이름으로 로드되고 필드는 비어 있게 되므로 `claude --debug`로 확인하세요.

| 필드 | 설명 |
|---|---|
| `name` | 스타일 이름 (`/config` 선택기에 표시). 기본: 파일 이름 |
| `description` | 설명 (선택기에 표시) |
| `keep-coding-instructions` | `true`면 **소프트웨어 개발용 지침을 유지**. 기본 `false` |
| `force-for-plugin` | **플러그인 스타일 전용.** `true`면 플러그인이 켜져 있을 때 이 스타일을 **자동 적용** (사용자의 `outputStyle` 설정보다 우선) |

> **`keep-coding-instructions`는 언제?** 말투·형식만 바꾸고 **코딩은 그대로** 하게 하려면 `true`. 소프트웨어 개발이 아닌 일(글쓰기 도우미, 데이터 분석가 등)에 쓸 스타일이면 **생략**합니다.

플러그인도 `output-styles\` 폴더로 스타일을 배포할 수 있습니다 ([플러그인](#/level3/plugins)).

## 어떤 기능을 써야 할까
출력 스타일은 **모든 응답**에 적용되고 **강제되지는 않습니다.**

| 원하는 것 | 쓸 것 | 이유 |
|---|---|---|
| 모든 응답의 **말투·길이·형식**, 또는 Claude의 **다른 역할** | **출력 스타일** | 세션 전체에 적용, 명령 하나로 전환 |
| 프로젝트의 **규칙·명령·구조**를 알게 하기 | [CLAUDE.md](#/level2/init-claudemd) | 어떤 스타일이든 계속 로드됨 |
| **특정 작업**의 절차(릴리스 체크리스트, 리뷰 절차) | [스킬](#/level3/skills) | 부를 때만 로드되어 관계없는 응답에 영향 없음 |
| **매번 예외 없이** 일어나야 하는 일 (수정 후 서식 정리, 명령 차단) | [훅](#/level3/hooks) | Claude Code가 직접 실행하므로 Claude가 따르는지에 달리지 않음 |
| 자기 지침·모델·도구를 가진 **전담 보조** | [서브에이전트](#/level3/subagents-advanced) | 별도 컨텍스트에서 실행하고 요약만 돌려줌 |
| 시작할 때 지침을 **더하기** | `--append-system-prompt` | 시스템 프롬프트에 덧붙임 |

이 기능들은 **함께** 씁니다. 예: `CLAUDE.md`로 "무엇을 알아야 하는지", 출력 스타일로 "어떻게 답할지", 훅으로 "반드시 일어나야 할 일".

## 출력 스타일이 동작하는 방식
- Claude Code가 활성 스타일의 지침을 **매 요청과 함께** 보냅니다
- 기본 제공 스타일은 **소프트웨어 개발 지침 + 자기 지침**이고, 직접 만든 스타일은 `keep-coding-instructions: true`일 때만 개발 지침을 유지합니다
- `--append-system-prompt`와 다르게 스타일은 **이름으로 고르고 바꾸는** 방식이라 상황별로 전환하기 편합니다

## 확인 체크
- [ ] `/output-style`로 목록과 현재 스타일을 확인했다
- [ ] `/output-style concise`로 전환하고 응답이 짧아지는 것을 봤다
- [ ] (선택) `.claude\output-styles\`에 스타일 파일을 만들고 Claude Code를 **다시 시작**해 고를 수 있는지 확인했다

## 자주 하는 실수
- `outputStyle` 값을 **소문자**로 씀 → 설정 파일에서는 `Explanatory`처럼 정확히 써야 합니다
- 새 스타일 파일을 만들고 **재시작하지 않음** → 터미널은 시작할 때 읽습니다
- **스타일이 규칙을 보장**한다고 믿음 → 지침일 뿐입니다. 필수 규칙은 훅
- Proactive로 바꾸면 **권한 확인이 사라진다**고 생각함 → 권한 모드는 그대로입니다
- 코딩용 스타일인데 `keep-coding-instructions`를 **빼먹음** → 코딩 지침이 빠집니다
- 철자 틀린 frontmatter 필드 → 조용히 무시됩니다
