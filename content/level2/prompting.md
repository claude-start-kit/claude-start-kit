# 잘 시키는 법

> Claude는 **내 PC 파일은 볼 수 있지만, 내 머릿속은 볼 수 없습니다.** 구체적일수록 한 번에 끝납니다.

## 나쁜 요청 vs 좋은 요청

| 나쁜 요청 | 좋은 요청 |
|---|---|
| "보고서 정리해 줘" | "`@report.md`를 읽고 **임원용 5줄 요약**으로 바꿔 줘. 숫자는 그대로 두고" |
| "버그 고쳐 줘" | "로그인 버튼을 누르면 **빈 화면이 나옴**. `@src/login.js`를 보고 원인을 찾아 고친 뒤 테스트를 돌려 줘" |
| "더 좋게 만들어 줘" | "제목을 15자 이내로, 존댓말로 3가지 안을 제안해 줘" |

## 4가지 습관

**1. 파일은 `@`로 지정**
`@` 뒤에 경로를 치면 자동 완성됩니다. 파일 내용이 대화에 들어갑니다.

**2. 끝났다는 기준을 주기**
"완료되면 `npm test`가 통과해야 해" 처럼 **확인 방법**을 알려 주세요. 스스로 확인하고 고칩니다.

**3. 애매하면 먼저 인터뷰 시키기**
```text
이 기능의 명세를 쓸 수 있을 때까지 나에게 질문해 줘. 다 끝나면 SPEC.md로 저장해 줘
```

**4. 이상하면 바로 `Esc`**
엉뚱한 방향이면 **즉시 멈추고** 다시 시키세요. 두 번 고쳐도 안 되면 `/clear` 후 더 구체적으로 다시 요청하는 편이 빠릅니다.

## 입력 단축키
| 입력 | 의미 |
|---|---|
| `@파일` | 파일 지정 |
| `! 명령` | 셸 명령을 직접 실행 (터미널 전용) |
| `Alt+V` | 클립보드 이미지 붙여넣기 (Windows) |
| `Shift+Enter` / `Ctrl+J` | 줄바꿈 |
| `Esc` | 작업 중지 / 빈 입력에서 두 번 → `/rewind` |

## 확인 체크
- [ ] `@`로 파일을 지정해서 요청해 봤다
- [ ] 요청에 "완료 기준"을 한 줄 넣어 봤다

## 자주 하는 실수
- **한 번에 너무 많이** 요청 → 단계로 나누기
- 결과를 **확인하지 않고** 다음 단계로 진행
