# 프로젝트 폴더 만들기

> Claude Code는 **파일을 읽고 쓸 수 있습니다.** 그래서 **전용 폴더를 만들고, 그 안에서 실행하는 것**이 안전합니다.

## 왜 폴더를 따로 만드나요?
- `claude`는 **실행한 폴더**를 작업 공간으로 삼아, 그 안의 파일을 읽고 고칩니다.
- 문서·사진이 가득한 폴더에서 실행하면 **관련 없는 파일까지** 작업 대상이 됩니다.
- 프로젝트마다 폴더가 따로 있으면 **무엇을 맡겼는지**, **무엇이 바뀌었는지** 한눈에 보입니다.
- 나중에 설치할 git도 **폴더 단위**로 변경 이력을 기록합니다.

## 만들고 실행하기
PowerShell에서 아래를 차례로 입력하세요.

```powershell
cd ~                 # 내 사용자 폴더로 이동
mkdir my-project     # 새 폴더 만들기
cd my-project        # 그 폴더로 들어가기
claude               # 여기서 Claude Code 실행
```

- 폴더 이름은 **영문·숫자·하이픈(-)** 으로, 공백 없이 짓는 것이 편합니다.
- 실행하기 전에 `pwd`로 **지금 위치**를 꼭 확인하세요.
- 이미 만들어 둔 `test-project`가 있다면 그대로 써도 됩니다.

## 이런 곳에서는 실행하지 마세요
| 위치 | 이유 |
|---|---|
| `C:\` 같은 드라이브 최상위 | 시스템 파일까지 범위에 들어갑니다 |
| 내 사용자 폴더 전체(`C:\Users\내이름`) | 문서·다운로드·바탕화면이 모두 범위에 들어갑니다 |
| 중요한 문서가 든 폴더 | 파일이 잘못 바뀔 수 있습니다 (원본은 복사해 두세요) |

> 얼마나 자주 허용 여부를 묻는지는 **권한 모드**에 따라 다릅니다([권한 모드](#/level2/permissions) 참고). 어떤 모드든 처음부터 범위를 좁게 시작하면 실수가 줄어듭니다.

## 확인 체크
- [ ] 내 프로젝트 폴더를 만들었다
- [ ] `pwd`로 그 폴더에 있는 것을 확인하고 `claude`를 실행했다

## 자주 하는 실수
- 터미널을 연 위치(사용자 폴더 등)에서 **그대로 `claude` 실행** → 먼저 `cd`로 프로젝트 폴더로 이동
- 프로젝트마다 폴더를 나누지 않고 **한 폴더에 계속 섞기** → 주제가 다르면 새 폴더를 만드세요
