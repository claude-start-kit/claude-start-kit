# 되돌리기 (/rewind)

> Claude가 잘못 고쳤어도 괜찮습니다. **한 번의 명령으로 이전 상태**로 돌아갑니다.

![rewind와 git](assets/img/rewind-vs-git.svg)

## 여는 방법
- `/rewind` (별칭 `/checkpoint`, `/undo`)
- 입력창이 **비어 있을 때** `Esc`를 두 번

> 입력창에 글자가 있을 때 `Esc` 두 번은 입력만 지웁니다.

## 선택할 수 있는 것
되감을 프롬프트를 고른 다음 동작을 선택합니다.

| 메뉴 | 효과 |
|---|---|
| Restore code and conversation | 코드와 대화 모두 그 시점으로 |
| Restore conversation | 대화만 되돌림 (코드는 그대로) |
| Restore code | 코드만 되돌림 (대화는 그대로) |
| Summarize from here | 여기 **이후** 대화를 요약해 공간 확보 |
| Summarize up to here | 여기 **이전** 대화를 요약하고, 이후 메시지는 그대로 |
| Never mind | 변경 없이 목록으로 돌아감 |

그 지점 뒤에 되돌릴 **코드 변경이 없으면** 두 코드 복원 메뉴는 보이지 않습니다. 요약은 디스크의 파일을 바꾸지 않고, 원래 메시지는 세션 기록에 남습니다.

프롬프트를 보낼 때마다 체크포인트가 자동 저장되고, 세션마다 최근 100개 체크포인트의 파일 스냅샷을 보관합니다.

## 한계 (꼭 읽어 보세요)
- **bash 명령으로만 바뀐 파일**은 추적되지 않습니다
- **서브에이전트가 고친 파일**은 대부분 복원되지 않습니다
- **내가 직접** 고친 파일이나 다른 세션의 변경은 보통 추적되지 않습니다
- 스냅샷은 기본적으로 **약 30일 뒤 삭제**됩니다. 지워진 뒤에는 되돌리기가 실패할 수 있습니다

공식 문서는 체크포인트를 "빠른 세션 단위 복구"용으로 설명하며 **Git을 대체하지 않는다**고 안내합니다. 링크 파일 처리 같은 세부 제한은 [공식 문서](https://code.claude.com/docs/ko/checkpointing)에서 확인하세요.

## 안전한 습관
```text
1. 큰 작업 전에는 git commit 으로 저장
2. 작업 중 이상하면 Esc 로 중단
3. 이전 상태로 → /rewind
4. 오래 남기고 싶은 상태 → git commit
```

## 확인 체크
- [ ] `/rewind` 메뉴를 열어 봤다
- [ ] 되돌리기가 **안 되는 경우**를 설명할 수 있다

## 자주 하는 실수
- rewind만 믿고 **커밋하지 않음** → 스냅샷은 기본적으로 약 30일 뒤 삭제되고, bash로만 바뀐 파일은 처음부터 되돌릴 수 없습니다
