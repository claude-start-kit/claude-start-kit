# 플랜 모드

> **고치기 전에 먼저 이해하고 계획합니다.** 큰 변경에서 실수를 가장 싸게 막는 방법입니다.

![플랜 모드 흐름](assets/img/plan-mode-flow.svg)

## 켜는 방법
| 방법 | 어떻게 |
|---|---|
| 단축키 | `Shift+Tab`을 눌러 **plan mode on** 표시가 나올 때까지 |
| 명령 | `/plan 로그인 기능 개선` |
| 시작할 때 | `claude --permission-mode plan` |

## 승인 화면
계획이 완성되면 선택지가 나옵니다.
- **Yes, and use auto mode / auto-accept edits** — 바로 실행
- **Yes, manually approve edits** — 실행하되 수정마다 확인
- **No, keep planning** — 계획을 더 다듬기

계획서를 직접 고치고 싶으면 **`Ctrl+G`** (기본 편집기에서 열림).

## 이렇게 써 보세요
```text
/plan 매주 쌓이는 회의록 txt 파일을 표로 정리하는 스크립트를 만들고 싶어.
먼저 필요한 파일과 단계를 계획해 줘. 아직 파일은 만들지 마.
```

## 이럴 때 특히 유용
- **처음 보는 폴더**를 다룰 때
- 파일 **여러 개를 바꿔야** 할 때
- 방향이 **애매할** 때

## 확인 체크
- [ ] 플랜 모드에서 계획서를 받아 봤다
- [ ] "No, keep planning"으로 수정을 요청해 봤다

## 자주 하는 실수
- 앱 만들기 같은 **복잡한 요청을 플랜 모드 없이 바로** 시킴 → 방향이 어긋나도 이미 파일이 많이 바뀐 뒤에야 알게 됩니다. 먼저 계획부터 받으세요
- 계획 승인 화면에서 플랜 모드를 끄려고 **`Shift+Tab`을 누름** → 끄는 것이 아니라 **계획을 승인**한 것이 되어 바로 실행됩니다. 승인하지 않고 나가려면 먼저 `Esc`를 누르세요
- 계획을 **읽지 않고** Yes
