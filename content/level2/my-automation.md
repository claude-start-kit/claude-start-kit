# 실전: 내 업무 자동화 하나 만들기

> 앞에서는 우리가 준 예제를 따라 했습니다. 이번에는 **내 업무 하나**를 골라 직접 자동화해 봅니다. 이 한 번을 해 보면, 그다음부터는 다른 업무도 같은 방식으로 만들 수 있습니다.

## 완성 모습
![주간 보고 초안 결과](assets/img/shots/my-automation.png)

> 예시는 **주간 업무 메모 → 주간 보고 초안**입니다. 여러분은 이 자리에 **자기 업무**를 넣습니다.

## 1단계 — 자동화할 업무 고르기
처음에는 작고 확인하기 쉬운 업무가 좋습니다. 아래 기준으로 골라 보세요.

| 기준 | 이렇게 고르세요 |
|---|---|
| 얼마나 자주? | 매주·매일 반복하는 일 |
| 입력과 결과 | "무엇을 주면 무엇이 나온다"가 분명한 일 |
| 틀렸을 때 | **내가 결과를 읽고 바로잡을 수 있는** 일 |
| 정보 | 개인정보·고객 정보·기밀이 **없어도** 연습할 수 있는 일 |

| 이런 업무가 좋아요 | 이런 업무는 나중에 |
|---|---|
| 주간 보고·메일 회신 **초안** 쓰기 | 결재·승인처럼 **사람이 판단**해야 하는 일 |
| 메모·회의록을 표로 정리 | 틀리면 되돌리기 어려운 일(발송, 삭제) |
| 엑셀(CSV)에서 이상한 값 찾기 | 고객·직원 정보가 꼭 필요한 일 |

## 2단계 — 입력과 결과를 한 문장으로 쓰기
아래 빈칸을 채워 보세요. 이 한 문장이 Claude에게 할 요청의 뼈대가 됩니다.

```text
(입력)을 읽고 (결과)를 만들어 줘.
없는 정보는 (어떻게 처리할지) 해 줘.
```

예시: `week-memo.txt를 읽고 주간 보고 초안을 만들어 줘. 없는 내용은 지어내지 말고 추정한 부분은 표시해 줘.`

## 3단계 — 가짜 데이터로 먼저 만들기
**실제 업무 파일을 바로 넣지 마세요.** 먼저 비슷한 모양의 **가짜 데이터**로 만들어 보고, 잘 되면 그때 내 업무에 적용합니다. 회사 정보가 Claude에 들어가는 일을 처음부터 막을 수 있습니다.

```powershell
cd ~
mkdir weekly-demo
cd weekly-demo
Set-Content week-memo.txt -Encoding UTF8 "월: 신제품 소개서 초안 작성. 화: 거래처 A사 견적 문의 회신. 수: 소개서 팀장 검토 요청, 수정 의견 2건. 목: 소개서 수정 완료, 월간 매출 엑셀 정리 시작. 금: 엑셀 정리 80% 완료, 나머지는 다음 주. 이슈: 거래처 B사 답변 아직 없음."
git init -b main
claude
```
> 위는 예시입니다. **내 업무에 맞는 가짜 메모**로 바꿔서 만드세요. 이름·회사명·금액은 모두 지어낸 것으로 쓰세요.

## 4단계 — 계획하고, 만들고, 대조하기
1. `Shift+Tab`으로 플랜 모드를 켜고 계획을 먼저 받습니다.
   ```text
   week-memo.txt를 읽고 주간 보고 초안을 report.md로 만드는 방법을 계획해 줘
   ```
2. 계획을 읽고 승인한 뒤 실행합니다.
   ```text
   계획대로 report.md를 만들어 줘. '이번 주 한 일', '다음 주 계획', '이슈' 세 항목으로 쓰고, 메모에 없는 내용은 지어내지 말고 추정한 부분은 따로 표시해 줘
   ```
3. **원문과 직접 대조합니다.** 메모에 없는 내용이 들어가지 않았는지, 빠진 일이 없는지 봅니다.

위 화면에서 Claude는 메모에 없는 내용을 **`※ 추정`으로 따로 표시**하고, 어떤 건인지 모르는 부분은 알려 달라고 되물었습니다. 이렇게 **"지어내지 말고 추정은 표시해 줘"**라고 시키면 사람이 확인할 곳이 눈에 보입니다.

## 5단계 — 내 업무에 맞게 고치고 남기기
결과가 마음에 들지 않으면 **어디를 어떻게** 바꿀지 구체적으로 말합니다.

```text
'이번 주 한 일'은 날짜 순서 말고 프로젝트별로 묶어 줘. 문장은 '~했습니다' 말투로 짧게
```

마음에 드는 모양이 나오면 규칙을 CLAUDE.md에 남겨서 **다음에도 같은 방식으로** 쓰게 합니다.

```text
방금 정한 보고서 규칙(세 항목, 프로젝트별 묶기, '~했습니다' 말투, 추정은 표시)을 CLAUDE.md에 적어 줘
```

마지막으로 내 진짜 업무 파일로 같은 요청을 해 봅니다. 이때는 **회사 정책을 먼저 확인**하세요.

## 결과를 꼭 검증하세요
- AI가 만든 초안은 **초안**입니다. 보내기 전에 **내가 읽고** 사실과 다른 곳을 고칩니다.
- `※ 추정`으로 표시된 부분은 메모에 없던 내용이므로 **직접 확인하거나 지웁니다.**
- 날짜·숫자·이름은 특히 틀리기 쉬우니 원문과 하나씩 대조합니다.

## 확인 체크
- [ ] 내 업무에서 자동화할 일 하나를 골랐다
- [ ] 가짜 데이터로 결과를 만들어 봤다
- [ ] 원문과 직접 대조해 틀린 곳이나 추정한 곳을 찾았다
- [ ] 규칙을 CLAUDE.md에 남겼다

## 자주 하는 실수
- **실제 기밀·개인정보 파일을 바로 넣음** → 가짜 데이터로 먼저 연습하고, 실제 파일은 회사 정책을 확인한 뒤에
- **한 번에 너무 큰 업무를 시킴** → 작은 업무 하나부터. 잘 되면 조금씩 넓히기
- **결과를 검증 없이 공유** → 사실과 다른 내용이 섞여 있을 수 있음
- "잘 써 줘"처럼 **막연하게** 요청 → 입력과 결과, 없는 정보 처리 방법을 한 문장으로 적기
