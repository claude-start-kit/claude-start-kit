# 실전: PPT 똑똑하게 만들기

> "PPT 만들어 줘" 한 줄로 시키면 **글만 빽빽한 슬라이드**가 나오기 쉽습니다. 이번에는 **① 내용 정리 → ② 슬라이드 개요 → ③ 파일 만들기 → ④ 확인 → ⑤ 고치기** 순서로 나눠서 시키고, 발표에 쓸 만한 `.pptx` 파일까지 만들어 봅니다.

## 왜 나눠서 시킬까
PPT가 어색한 이유는 대부분 **디자인이 아니라 내용 구성** 때문입니다. 그래서 먼저 "무엇을 말할지"를 정하고, 그다음에 파일을 만듭니다.

| 한 번에 시킬 때 | 나눠서 시킬 때 |
|---|---|
| 슬라이드마다 문장이 길고 메시지가 흐림 | 슬라이드마다 **말하고 싶은 것 한 줄**이 정해짐 |
| 마음에 안 들면 전체를 다시 만들어야 함 | **개요(텍스트)** 단계에서 싸게 고치고, 파일은 마지막에 만듦 |
| 어디가 지어낸 내용인지 알 수 없음 | 없는 정보는 **빈칸·추정 표시**로 남김 |

## 1단계 — 재료와 목적 정하기
Claude에게 일을 넘기기 전에 아래 네 가지를 먼저 정합니다. 이것만 정해도 결과가 크게 달라집니다.

| 정할 것 | 예시 |
|---|---|
| **누구에게** | 팀장·고객·신입 팀원 |
| **무엇을 하게 하려고** | 승인을 받으려고 / 현황을 공유하려고 / 교육하려고 |
| **얼마 동안** | 5분 → 슬라이드 5~7장 정도 |
| **재료** | 메모·회의록·표(CSV) 등 이미 있는 자료 |

처음에는 **가짜 데이터**로 연습하세요. 실제 사내 자료를 바로 넣지 말고, 같은 모양의 지어낸 내용으로 먼저 만들어 보고, 잘 되면 회사 정책을 확인한 뒤에 실제 자료에 적용합니다.

```powershell
cd ~
mkdir ppt-demo
cd ppt-demo
Set-Content memo.txt -Encoding UTF8 "신제품 '모아노트'(가짜 이름) 소개 발표 준비. 대상: 영업팀. 목적: 영업팀이 고객에게 3가지 장점을 설명할 수 있게 하기. 장점1: 메모를 자동으로 요약. 장점2: 팀원과 실시간 공유. 장점3: 모바일에서도 사용. 가격: 월 5,000원(가짜). 출시일: 다음 달 1일. 고객 문의가 많은 질문: 기존 메모를 옮길 수 있나요? 오프라인에서도 되나요?"
git init -b main
claude
```
> 위는 예시입니다. **내 발표 주제에 맞는 가짜 메모**로 바꿔서 만드세요. 제품명·금액·날짜는 모두 지어낸 것으로 쓰세요.

## 2단계 — 파일보다 먼저 '슬라이드 개요'를 받기
**아직 PPT 파일을 만들지 않습니다.** 먼저 슬라이드별 제목과 핵심 메시지를 **텍스트로** 받아서 읽어 봅니다.

이렇게 요청합니다. 개요가 이미 "계획" 역할이라 플랜 모드는 필요 없습니다.

```text
memo.txt를 읽고 영업팀 대상 5분 발표용 슬라이드 개요를 outline.md로 만들어 줘.
- 6장 이내, 슬라이드마다 '제목(결론 문장)'과 '핵심 메시지 한 줄', 들어갈 항목 3개 이하
- 메모에 없는 내용은 지어내지 말고 [확인 필요]로 표시해 줘
- 마지막 장은 '고객이 자주 묻는 질문'으로
```

개요를 읽을 때는 아래를 확인합니다.

- 각 슬라이드 제목이 **"장점"** 같은 이름표가 아니라 **"메모를 자동으로 요약해 줍니다"** 같은 **결론 문장**인가
- 한 슬라이드에 **메시지가 하나**인가
- `[확인 필요]` 표시가 붙은 곳이 있다면 **내가 채워야 하는 부분**입니다. 메모에 없던 정보를 Claude가 만들어 넣은 것은 아닌지 확인하세요

마음에 들지 않으면 파일을 만들기 **전에** 여기서 고칩니다.

```text
3번 슬라이드는 '모바일에서도 사용'과 합치고, 2번과 3번 순서를 바꿔 줘
```

## 3단계 — 개요로 .pptx 파일 만들기
개요가 마음에 들면 파일을 만듭니다.

```text
outline.md대로 moanote.pptx를 만들어 줘.
- 16:9, 슬라이드당 글자는 짧게, 제목은 크게
- 발표자 노트에 각 장에서 말할 내용을 2~3문장씩 넣어 줘
- 색은 두 가지 이내로 통일해 줘
```

- Claude가 파일을 만들 도구(PPT 생성 라이브러리 등)를 **설치해도 되는지 물어볼 수 있습니다.** 어떤 명령인지 읽고 허용하세요. 모르는 명령이면 "이게 뭐 하는 명령이야?"라고 먼저 물어보세요
- 같은 폴더에 **`moanote.pptx`** 가 생깁니다. 파일이 만들어졌는지는 `ls`로 확인할 수 있습니다.

```powershell
ls *.pptx
start moanote.pptx
```
`start`는 파일을 PowerPoint(또는 연결된 프로그램)로 엽니다. 파일을 열어 **내 눈으로** 확인하는 것이 가장 정확합니다.

## 4단계 — 눈으로 확인하고 Claude에게도 점검시키기
열어 보면서 아래를 봅니다.

| 확인할 것 | 이렇게 보세요 |
|---|---|
| **글자가 넘치거나 겹치지 않는가** | 슬라이드를 하나씩 넘기며 확인. 글이 상자 밖으로 나가는 곳은 없는지 |
| **내용이 원문과 맞는가** | 숫자·날짜·이름을 `memo.txt`와 하나씩 대조 |
| **슬라이드 수와 순서** | 개요와 같은지 |
| **발표자 노트** | 슬라이드 보기 아래에 노트가 들어갔는지 |

Claude에게도 점검을 시킬 수 있습니다.

```text
moanote.pptx를 다시 읽어서 슬라이드별 제목, 글자 수, 발표자 노트 유무를 표로 보여 줘.
글자가 많은 슬라이드와 outline.md와 다른 부분이 있으면 알려 줘
```

> 이 점검은 **파일 안의 글자**를 읽는 것이라 "보기에 예쁜지"는 알려 주지 못합니다. 레이아웃이 어색한지는 직접 열어서 판단하세요.

## 5단계 — 구체적으로 고치기
막연하게 "더 예쁘게"라고 하면 전체가 바뀝니다. **어느 슬라이드의 무엇을** 어떻게 바꿀지 말합니다.

```text
3번 슬라이드의 항목 3개를 한 줄씩 짧게 줄이고 글자 크기를 키워 줘.
다른 슬라이드는 건드리지 마
```

> 고칠 때 **PowerPoint에서 같은 파일을 열어 둔 채**라면 저장에 실패할 수 있습니다. 파일을 닫고 다시 시키거나, `moanote-v2.pptx`처럼 **새 이름**으로 만들게 하세요.

### 자주 하는 고침 요청

| 문제 | 이렇게 말하세요 |
|---|---|
| 글이 너무 많다 | `슬라이드당 항목은 3개 이하, 항목당 20자 이내로 줄여 줘` |
| 어디를 강조할지 모르겠다 | `슬라이드마다 가장 중요한 단어 하나만 굵게 해 줘` |
| 표가 필요하다 | `3번 슬라이드의 비교 내용을 2열 표로 바꿔 줘` |
| 발표 시간이 넘친다 | `5분 발표 기준으로 6장을 5장으로 줄이고 어떤 걸 뺐는지 알려 줘` |
| 색이 정신없다 | `색은 제목용 한 가지와 강조용 한 가지만 쓰도록 통일해 줘` |

## 우리 회사 양식(템플릿)으로 만들기
이미 쓰는 **회사 양식 파일**이 있다면 같은 폴더에 두고 이렇게 시킵니다.

```text
company-template.pptx의 슬라이드 마스터(글꼴·색·로고 위치)를 그대로 써서 outline.md로 새 발표 자료를 만들어 줘
```
- 양식에 **기밀이 있는지** 먼저 확인하세요. 양식 파일은 Claude가 읽을 수 있는 자료가 됩니다
- 양식과 똑같이 나오는지는 **열어서 직접 확인**해야 합니다. 안 맞는 곳은 어디가 다른지 구체적으로 알려 주세요

## 결과를 꼭 검증하세요
- AI가 만든 슬라이드는 **초안**입니다. 발표 전에 **내가 처음부터 끝까지 넘겨 보고** 사실과 다른 곳을 고칩니다.
- `[확인 필요]` 표시는 **내가 채워야 할 곳**입니다. 지우지 말고 확인한 뒤에 바꾸세요.
- 숫자·날짜·가격·이름은 특히 틀리기 쉬우니 원문과 대조하세요.
- 사내 기밀이나 개인정보가 들어가는 자료라면 **회사 정책을 먼저 확인**하세요.

## 확인 체크
- [ ] 청중·목적·시간·재료 네 가지를 먼저 정했다
- [ ] 파일을 만들기 전에 `outline.md`로 슬라이드 개요를 받았다
- [ ] `.pptx`를 만들고 `start`로 직접 열어 봤다
- [ ] 글자가 넘치는 곳과 원문과 다른 곳을 찾아 고쳤다
- [ ] 규칙을 `CLAUDE.md`에 남겼다

## 자주 하는 실수
- **"PPT 만들어 줘" 한 줄로 시킴** → 개요(`outline.md`)부터 받고, 승인한 뒤에 파일 만들기
- **슬라이드에 문장을 길게 넣음** → 슬라이드는 발표자를 돕는 것이고, 말할 내용은 **발표자 노트**에
- **"더 예쁘게"처럼 막연히 고쳐 달라고 함** → 몇 번 슬라이드의 무엇을 바꿀지 구체적으로
- **PowerPoint에서 연 채로 다시 만들게 함** → 파일을 닫거나 새 이름으로
- **확인 없이 발표에 씀** → 숫자와 이름을 원문과 대조하고, 슬라이드를 직접 넘겨 보기
- **실제 기밀 자료를 바로 넣음** → 가짜 데이터로 먼저 연습하고, 회사 정책 확인 후 적용
