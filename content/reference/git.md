# 자주 쓰는 Git 명령

> Git 명령은 150개가 넘지만 매일 쓰는 것은 몇 십 개뿐입니다. **자주 쓰는 명령만 골라** 상황별로 정리했습니다. 위 검색창에 명령 이름이나 하고 싶은 일(예: `되돌리기`, `stash`, `충돌`)을 입력하세요. Claude Code에게 "커밋해 줘"라고 시켜도 결국 이 명령들이 실행됩니다.

## 읽는 법
- `<이름>`은 **직접 채울 값**, `[옵션]`은 **있어도 되고 없어도 되는 값**입니다
- ⚠ 표시는 **작업 내용을 잃을 수 있는 위험한 명령**입니다. 실행 전에 `git status`로 확인하세요
- 이 표의 명령은 이 프로젝트를 만든 PC의 Git 2.56(Windows)에서 이름과 옵션이 실제로 있는지 확인했습니다. 버전에 따라 다를 수 있습니다
- 여기에 없는 명령이나 옵션은 `git help <명령>` 또는 공식 문서 [git-scm.com/docs](https://git-scm.com/docs)에서 찾으세요

## 시작·설정 (8)
| 명령 | 설명 | 비고 |
| :- | :- | :- |
| `git --version` | 설치된 Git 버전 확인 | |
| `git init` | 현재 폴더를 Git 저장소로 만들기 | |
| `git clone <주소>` | 원격 저장소를 내 PC로 복사 | 폴더가 새로 생김 |
| `git config --global user.name "이름"` | 커밋에 기록될 이름 설정 | 공개 저장소에 올릴 때는 **공개해도 되는 이름**인지 확인 |
| `git config --global user.email "메일"` | 커밋에 기록될 이메일 설정 | 공개 저장소에 올릴 때는 **공개해도 되는 주소**인지 확인 |
| `git config --global init.defaultBranch main` | 새 저장소의 첫 브랜치 이름을 `main`으로 | |
| `git config --list` | 현재 적용 중인 설정 전체 보기 | |
| `git help <명령>` | 그 명령의 공식 설명 보기 | 예: `git help rebase` |

## 상태·기록 확인 (11)
| 명령 | 설명 | 비고 |
| :- | :- | :- |
| `git status` | 바뀐 파일, 스테이징된 파일, 현재 브랜치 보기 | **가장 자주 쓰는 명령** |
| `git status -s` | 한 줄 요약으로 상태 보기 | |
| `git diff` | 아직 add하지 않은 변경 내용 보기 | |
| `git diff --staged` | add해 둔(다음 커밋에 들어갈) 변경 내용 보기 | |
| `git log` | 커밋 기록 보기 | `q`로 종료 |
| `git log --oneline` | 커밋을 한 줄씩 보기 | |
| `git log --oneline --graph --all` | 모든 브랜치를 그래프로 보기 | |
| `git log -p <파일>` | 그 파일의 변경 이력을 내용과 함께 보기 | |
| `git show <커밋>` | 특정 커밋의 내용 보기 | 커밋은 해시 앞 7자리 정도로 지정 |
| `git blame <파일>` | 줄마다 마지막으로 고친 사람·커밋 보기 | |
| `git shortlog -sn` | 사람별 커밋 수 | |

## 변경 올리기 (add → commit) (9)
| 명령 | 설명 | 비고 |
| :- | :- | :- |
| `git add <파일>` | 그 파일을 다음 커밋에 포함하도록 스테이징 | |
| `git add .` | 현재 폴더 아래의 모든 변경을 스테이징 | 비밀 키·큰 파일이 섞이지 않았는지 `git status`로 먼저 확인 |
| `git add -p` | 변경을 조각 단위로 골라 스테이징 | |
| `git commit -m "메시지"` | 스테이징한 내용을 커밋 | |
| `git commit -am "메시지"` | 이미 추적 중인 파일의 변경을 add 없이 한 번에 커밋 | **새 파일은 포함되지 않음** |
| `git commit --amend` | 방금 한 커밋을 고치기(메시지 수정, 빠뜨린 파일 추가) | ⚠ **push하기 전에만** 사용 |
| `git rm <파일>` | 파일을 지우고 삭제를 스테이징 | |
| `git rm --cached <파일>` | 파일은 남기고 Git 추적만 중단 | `.gitignore`에 추가할 때 함께 사용 |
| `git mv <이전> <새이름>` | 파일 이름 바꾸기·이동 | |

## 브랜치 (13)
| 명령 | 설명 | 비고 |
| :- | :- | :- |
| `git branch` | 브랜치 목록 (현재 브랜치에 `*`) | |
| `git branch -vv` | 브랜치마다 마지막 커밋과 연결된 원격 브랜치 보기 | |
| `git branch <이름>` | 새 브랜치 만들기 (이동은 안 함) | |
| `git switch <이름>` | 그 브랜치로 이동 | |
| `git switch -c <이름>` | 새 브랜치를 만들면서 바로 이동 | |
| `git branch -m <새이름>` | 현재 브랜치 이름 바꾸기 | |
| `git branch -d <이름>` | 합쳐진 브랜치 삭제 | 아직 합치지 않았으면 거부됨 |
| `git branch -D <이름>` | 합치지 않았어도 브랜치 강제 삭제 | ⚠ 그 브랜치에만 있는 커밋은 찾기 어려워짐 |
| `git merge <브랜치>` | 그 브랜치를 **현재 브랜치에 합치기** | |
| `git merge --abort` | 충돌이 난 합치기를 취소하고 원래대로 | |
| `git rebase <브랜치>` | 현재 브랜치의 커밋을 그 브랜치 끝으로 옮겨 붙이기 | ⚠ 이미 push한 커밋에는 쓰지 않기 |
| `git rebase --abort` | 진행 중인 rebase를 취소 | |
| `git cherry-pick <커밋>` | 다른 브랜치의 커밋 하나만 가져오기 | |

## 원격 저장소 (GitHub 등) (10)
| 명령 | 설명 | 비고 |
| :- | :- | :- |
| `git remote -v` | 연결된 원격 저장소 주소 보기 | |
| `git remote add origin <주소>` | `origin`이라는 이름으로 원격 저장소 연결 | |
| `git remote set-url origin <주소>` | 원격 저장소 주소 바꾸기 | |
| `git fetch` | 원격의 새 내용을 **받아만 오기** (내 파일은 안 바뀜) | |
| `git pull` | 원격의 새 내용을 받아 **현재 브랜치에 합치기** | |
| `git pull --rebase` | 받아 온 뒤 내 커밋을 그 위로 옮겨 붙이기 | 기록이 한 줄로 깔끔해짐 |
| `git push` | 내 커밋을 원격에 올리기 | |
| `git push -u origin <브랜치>` | 처음 올릴 때 원격 브랜치와 연결하며 올리기 | 이후에는 `git push`만 |
| `git push --force-with-lease` | 다른 사람이 올린 것을 덮어쓰지 않는 조건으로 강제 push | ⚠ 공유 브랜치에서는 쓰지 않기. 그냥 `--force`보다 안전 |
| `git branch -r` | 원격 브랜치 목록 | |

## 되돌리기·임시 저장 (13)
| 명령 | 설명 | 비고 |
| :- | :- | :- |
| `git restore <파일>` | 수정한 파일을 **마지막 커밋 상태로** 되돌리기 | ⚠ 그 파일의 수정 내용이 사라짐 |
| `git restore --staged <파일>` | `git add`를 취소 (파일 내용은 그대로) | |
| `git reset --soft HEAD~1` | 마지막 커밋을 취소하고 **변경은 스테이징 상태로 유지** | |
| `git reset HEAD~1` | 마지막 커밋을 취소하고 변경은 **파일에 남김** (스테이징 해제) | |
| `git reset --hard HEAD~1` | 마지막 커밋을 취소하고 **변경까지 삭제** | ⚠ 위험. 복구는 `git reflog`로 가능한 경우가 있음 |
| `git revert <커밋>` | 그 커밋을 **취소하는 새 커밋**을 만들기 | 이미 push한 커밋을 되돌릴 때 안전 |
| `git stash` | 작업 중인 변경을 임시로 치워 두기 | 새 파일은 기본적으로 포함되지 않음 |
| `git stash list` | 치워 둔 목록 보기 | |
| `git stash pop` | 가장 최근에 치워 둔 변경을 되돌려 놓고 목록에서 삭제 | |
| `git stash drop` | 가장 최근에 치워 둔 변경을 삭제 | ⚠ |
| `git reflog` | HEAD가 움직인 모든 기록 보기 | 잘못 지운 커밋·브랜치를 찾는 **구조 도구** |
| `git clean -n` | 지워질 **추적되지 않는 파일**을 미리 보기 | 실제로 지우지 않음 |
| `git clean -fd` | 추적되지 않는 파일과 폴더를 삭제 | ⚠ 위험. 반드시 `-n`으로 먼저 확인 |

## 태그·작업 폴더 (6)
| 명령 | 설명 | 비고 |
| :- | :- | :- |
| `git tag` | 태그 목록 | |
| `git tag -a v1.0 -m "메시지"` | 설명이 붙은 태그 만들기 | |
| `git push origin v1.0` | 태그를 원격에 올리기 | 태그는 `git push`에 자동으로 포함되지 않음 |
| `git worktree add <폴더> <브랜치>` | 다른 브랜치를 **별도 폴더**에 펼쳐 동시에 작업 | Claude Code의 `--worktree` 옵션이 이것을 이용 |
| `git worktree list` | 작업 폴더 목록 | |
| `git worktree remove <폴더>` | 작업 폴더 제거 | |

## 이럴 땐 이렇게 (상황별 해결집) (16)
| 상황 | 해결 | 비고 |
| :- | :- | :- |
| 방금 커밋 **메시지를 잘못** 썼다 | `git commit --amend -m "새 메시지"` | ⚠ push 전에만 |
| 커밋했는데 **파일 하나를 빠뜨렸다** | `git add <파일>` 후 `git commit --amend --no-edit` | ⚠ push 전에만 |
| 마지막 커밋을 취소하되 **작업 내용은 살리고** 싶다 | `git reset --soft HEAD~1` | |
| 마지막 커밋과 **작업 내용을 다 버리고** 싶다 | `git reset --hard HEAD~1` | ⚠ 위험 |
| **이미 push한** 커밋을 취소하고 싶다 | `git revert <커밋>` 후 `git push` | 기록을 지우지 않아 협업에 안전 |
| 파일을 **수정했는데 되돌리고** 싶다 | `git restore <파일>` | ⚠ 수정 내용이 사라짐 |
| `git add`를 **잘못** 했다 | `git restore --staged <파일>` | |
| 작업 중에 **다른 브랜치로 급히 이동**해야 한다 | `git stash` → `git switch <브랜치>` → (작업 후 돌아와) `git stash pop` | |
| **브랜치 이름**을 바꾸고 싶다 | 바꿀 브랜치에서 `git branch -m <새이름>` | 원격에 올린 브랜치는 원격에서도 따로 정리 필요 |
| 합치다가 **충돌**(`<<<<<<<`)이 났다 | ① 충돌 난 파일을 열어 `<<<<<<<`, `=======`, `>>>>>>>` 표시를 정리해 원하는 내용만 남김 ② `git add <파일>` ③ `git commit` (합치기를 포기하려면 `git merge --abort`) | Claude Code에게 "충돌 해결해 줘"라고 시켜도 됨 |
| `git push`가 **거부**됐다 (`rejected`, `non-fast-forward`) | 원격에 내가 모르는 새 커밋이 있다는 뜻입니다. `git pull --rebase` 후 다시 `git push` | |
| 실수로 **지운 브랜치·커밋**을 찾고 싶다 | `git reflog`에서 해시를 찾아 `git switch -c <복구브랜치> <해시>` | 오래되면 사라질 수 있음 |
| 이미 추적 중인 파일을 `.gitignore`에 넣었는데 계속 보인다 | `git rm --cached <파일>` 후 커밋 | 파일은 디스크에 남음 |
| 원격 저장소 주소를 **바꾸고** 싶다 | `git remote set-url origin <새주소>` | |
| `detached HEAD` 경고가 떴다 | 그 상태의 작업을 남기려면 `git switch -c <새브랜치>` | |
| **비밀 키를 커밋**해 버렸다 | 키를 **즉시 폐기하고 새로 발급**하세요. 기록에서 지우는 것만으로는 이미 노출된 키가 안전해지지 않습니다 | 공개 저장소라면 특히 중요 |
